# Rynvek Engine：生产池付款出生至自主代谢/摄食

## 设计依据与本批选择

原v1 §5.1.2/§5.2.1/§5.5的阵营启动资源、冻结生产造价及神经成本，不等于身体可免费获能。原最终讨论D156要求神经计算受真实资源约束；本仓库既有 `EnergyAccount` 定义1 milli = 4000 q，场营养经真实经济1:1转为Biomass，个体余量也按此精确映射转回Biomass。复用这一**已有实现映射**，不声称原规范已规定出生费具体值。

本批选择当前存在的**阵营生产池Biomass**，不是新造亲本或母体状态。只覆盖显式PvE契约中的**SpawningVat生产的玩家Forager**。原单位生产造价仍在QueueUnit时扣除；新增必填正 `birth_energy_milli` 在实际孵化完成前另行实扣，不能把已花掉的造价再次当能量。例1000 milli只作明确实验参数（1 Biomass），不冒充冻结平衡。

## 单一当前契约与真实入口

```json
{"title":"有来源出生实验","template":"arena_pve","map_seed":57,
 "ecology":{"basal_cost_micro_per_tick":1000,"reserve_ticks":1000,"birth_energy_milli":1000}}
```

通过原真实POST /api/v1/worlds创建。三个参数必须显式提供；出生费为正、u32范围，使用现有精确非负换算；原代谢/预留溢出验证继续保留。1000 Tick预留在贫营养红绿用例中用于保留已付款出生池，避免余量转回阵营干扰计算付款的观察，不是新增默认规则。实际用户可配置预留，原余量转账政策没有暗改。

整个MatchConfig继续入config_root，无第二份出生配置或状态源。当前快照CONF领域格式标识改为 `rynvek-arena/4`，仅识别这一当前格式；不保留Arena/3或两参数对象兼容分支，不自动补出生费。通用快照容器及Tick协议识别仍保留，无迁移框架、无新生态模式。

## 付款、停产与原子性

1. QueueUnit仍支付原冻结物料价并排队，ProductionJob不增加影子托管账户。
2. run_vat在真实供电倒计时到最后一Tick时，按原实体序号顺序检查并扣当前Biomass出生预算。
3. 缺能：**拒绝本Tick出生**，队首保持最后一Tick，不弹队、不分配实体、不扣能量；原已付造价仍按既有CancelQueue/拆除规则退款。并非承诺此前排队的物料价也未扣除。
4. 足能：同一权威候选步骤先扣一次生产池，再弹队、spawn_unit并把已支付额度作为身体账户真实received_q/stored_q；不是from_milli无来源的初始化注资。
5. 原局部场摄食、真实脑Epoch付款、基础代谢、同池预留/余量回转及死亡回收随后执行。出生收入也激活原received_q>0的生存判断，贫营养出生不再因“从未摄食”无限免基础死亡。
6. 原ArenaRuntime候选事务、Actor持久化后唯一发布、ECOL/NEUR、规范根、快照和WAL照常负责原子性与确定性。资金不能在中断/重试时多扣；取消未付款的待产任务也不能退一笔未付出生能量。

## 守恒与真实验证

行为红测基线7da9175：真实建设/排队/贫营养孵化得到received_q=0，而指定实验应获4000000 q；余额不足999 milli仍免费出生，单位数4变5。修复后两断言保持。

- 贫营养ConductiveBasalt地图，没有Move、Harvest、注入身体账户或场补给：实际生产池扣费，真实LIF提交脑状态，基础费/发放费进入热耗且无欠费。
- 两真实孵化槽同Tick争用一份预算，仅实体序号在先者出生，后者停产；未透支、无重复收款。
- 候选已扣款/已出生后事务错误，源检查点字节不变；恢复后连续执行根完全一致。
- 实际余额从999补齐至1000后只出生一次；取消缺能任务仅退已支付物料价。
- 生产池 → 活体 → 热耗/原Biomass回转 → 自然耗尽或战斗残骸 → 实际环境场：严格核对出生总来源4000000 q = 剩余阵营Biomass×4000 + 热耗 + 遗骸剩余 + 场回收量。死亡不从原单位购买价造营养。
- 富营养真实孵化路径同时断言received_q大于已付款出生额度，额外收入为真实场量子；不能只靠出生注资掩盖环境摄食未发生。
- 同一认证TCP/WebSocket Actor在已有局部摄食场景后继续真实建槽、排队、出生；原生引擎逐批推进与服务Actor及Store检查点/WAL恢复的状态根、账户完全一致。
- 原跨契约快照/WAL拒绝、全参数根绑定、权限、迷雾/私有账户边界及全部守恒/计算/死亡断言保留；新增出生费改价入根与重封装拒绝。

完整门禁以本批最终冻结HEAD执行日志为准，不以定向测试替代。

## 尚未覆盖（不能称全生态）

- 初始Starter Kit、PvE野生出生及其他单位类型不从此生产费路径获能；这些出生来源/供能契约仍待统一设计。
- 没有实现亲本能量分配、自然分裂、繁殖动作/阈值、遗传谱系与跨代生态；没有添加人工适应度。
- 本批不靠不收费的自主移动解决饥饿；未建立完整移动/其他模型成本与自主寻粮选择。已付款出生能支持真实计算/有限生存，局部有食物可继续摄食，无食物最终会耗尽死亡。
- 常规RTS/PvP不启用该实验，原单位购买价/操作平衡不暗改。浏览器、真实硬件GPU、真PG、断电和24h长稳未验收；GL软件差分不算硬件验收。
